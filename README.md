# RAILNEX

Rail reservation application with a React/Vite frontend, FastAPI API, and PostgreSQL source of truth.

## Deployment layout

- Frontend and FastAPI API: one Vercel project using Vercel Services, configured by the root `vercel.json`.
- Database: managed PostgreSQL, provisioned separately and reachable from the API service. Vercel does not provide the PostgreSQL database for this project.
- Alternative API host: the included `render.yaml` remains available if you choose to host the API separately on Render instead of using Vercel Services.

## Deploy as one Vercel Services project

1. Provision a managed PostgreSQL database and allow the Vercel API service to connect to it.
2. Apply `database/RAILNEX_complete_postgresql.sql` to the empty database.
3. Import this repository into Vercel with the repository root as the project root. Do not set `frontend` as the project root; the root `vercel.json` defines both services and their public routing.
4. Set `DATABASE_URL` and a high-entropy `JWT_SECRET` for the `railnex-api` service in Vercel. Set `CORS_ORIGINS` to a JSON array of permitted origins if cross-origin clients are needed. Never put database credentials or JWT secrets in GitHub or frontend variables.
5. The frontend uses the same-origin `/api` path in production. Do not manually define `RAILNEX_API_URL`; it is generated by the service binding (which is available to server-side functions, not the current static Vite browser app).
6. Deploy and verify `/api/health` reports a connected database. Configure any additional production/preview CORS origins only if requests will be cross-origin.

## Local development

- Frontend: copy `frontend/.env.example` to `frontend/.env.local`, install dependencies in `frontend`, and run `npm run dev`.
- Backend: copy `backend/.env.example` to `backend/.env`, set your local database URL and a local-only JWT secret, install `backend/requirements.txt`, and run Uvicorn from the `backend` directory.
- Never commit `.env` files. Only the `.env.example` templates belong in Git.

## Push to GitHub

The project is tracked in GitHub. Review `git status` before committing to ensure local environment files, virtual environments, and build artifacts remain ignored.
